# 한국 단기 스윙(1~3일) 다종목 자동매매 — 리서치 & 개선 플랜

> 작성일: 2026-06-07 · 대상: alpha-mind
> 전제(사용자 확정): **일봉 데이터 기반 1~3일 초단기 스윙**(현 구조 유지, 분봉 미도입) · 일봉 신호 진입 + 실시간 TP/SL.
> 우선순위: ① 다종목 실행 아키텍처 → ② 리스크/자금관리 & 검증 → ③ 스크리닝 고도화.
> 산출물: 인용 리서치 + 현재 코드 기준 구체적 개선 플랜.

---

## 0. Executive Summary

- **현 시스템은 "단타"가 아니라 "일봉 신호 기반 1~7일 초단기 스윙 + 장중 실시간 청산"** 으로 이미 잘 설계돼 있다. 사용자 목표(1~3일 짧게 먹고 빠지기)와 정합. 분봉 도입 없이 **파라미터/청산/사이징/검증** 고도화로 목표 달성 가능.
- **가장 큰 즉효 갭 3가지**: ① **부분 청산(scale-out) 부재** — 항상 전량 매도라 "짧게 먹고 일부 남겨 추세 먹기"가 불가, ② **survivorship bias(생존편향)** — DB가 현재 상장 종목만 보유 → 스캔/백테스트 성과 과대평가(리서치상 모멘텀 백테스트 CAGR 26%→12%로 반토막 사례), ③ **레이트리밋 안전장치 부재** — KIS 초당 거래건수 초과(`EGW00201`) 위험을 종목 수 증가 시 중앙 제어 없음.
- **거래비용 팩트 업데이트 필요**: 2025.1.1부터 KOSPI/KOSDAQ 증권거래세 **0.18% → 0.15%** 인하(검증 3-0). 단, **2026년 재인상 가능성**은 본 리서치에서 확증 못 함 → 공식 출처 재확인 권장(아래 §1.1, §5).
- **사이징**: 현재 ATR 역가중(변동성 타깃팅의 단순형)은 방향이 맞다. **거래당 리스크(R) 기반 사이징 + 시장 국면 스케일링**(고변동 구간 노출 축소, 검증된 Kelly×(1−VIX percentile) 공식)으로 한 단계 올릴 수 있다.

> ⚠️ 검증 상태 표기: **[검증됨 n-0]** = 적대적 3표 검증 통과(찬성-반대 표결) · **[반증/주의]** = 검증에서 깨짐 → 신뢰 금지 · **[표준사실]** = 광범위 통용 사실(잔여 시점민감 항목만). 최종: **25 검증 / 1 반증 / 미해결 0**.

## 1. 리서치 결과 (출처 인용)

### 1.1 거래비용 — 거래세·슬리피지

- **[검증됨 3-0]** 2025.1.1부터 **KOSPI 증권거래세 0.15%** (거래세 0% + 농어촌특별세 0.15%), **KOSDAQ도 0.18%→0.15%**. 출처: ds-sec.co.kr(primary). → 현재 코드 `DEFAULT_SELL_TAX_PCT = 0.18`은 2025년 기준으로는 과대.
- **[주의]** 2026년 재인상(KOSDAQ 0.15→0.20, KOSPI 거래세분 0→0.05 부활) 관련 주장은 **불확실(unreliable 출처, 미검증)**. 오늘이 2026년이므로 **실제 적용 세율을 KRX/국세청 공식 자료로 반드시 재확인**할 것.
- **슬리피지**: 한국 단타 실측 0.03~0.1%대(중앙값 ~0.05%)라는 통념과 코드 가정(`DEFAULT_SLIPPAGE_PCT = 0.05`)이 일치. 단 저유동/시초가/VI 구간에선 훨씬 커짐 → 유동성 연동 슬리피지 모델 권장(§3.2).
- **함의**: 1~3일 스윙은 회전율이 높아 비용 민감도가 크다. **[표준사실]** 비용·슬리피지를 무시하면 연 15% 전략이 0 근처로 붕괴할 수 있음(starqube). 비용은 보수적으로 두되 **세율은 config화**하여 매년 갱신.

### 1.2 KIS OpenAPI 운영 제약 (다종목 모니터링의 핵심 병목)

- **[검증됨 3-0]** KIS OpenAPI는 **초당 거래건수 제한**이 있으며 초과 시 **`EGW00201` (초당 거래건수 초과)** 에러 반환. 출처: github.com/koreainvestment/open-trading-api(primary).
- **[검증됨 3-0]** 실무 통설 **REST ~20 req/s** 제한. **[검증됨 3-0]** 70종목을 단순 배치(20개씩, 0.2s)로 돌리면 종목당 2콜(분봉+현재가) 때문에 **~175 req/s(한도 875% 초과)** 발생. **[검증됨 2-0]** → **종목 수 기반 동적 배치(예: 70종목이면 batch 10 + 1.0s 지연 → 약 7초에 전종목)** 로 해결. **[검증됨 2-0]** KIS 처리량 ~20 calls/s 가 다종목 폴링의 핵심 제약. 출처: tgparkk.github.io, hky035.github.io(blog).
- **[검증됨 3-0]** **WebSocket은 한 세션/승인키당 실시간 등록 종목 수 한도(~41개)**, **[검증됨 3-0]** 세션은 계정(개발자센터 키)당 바인딩 → **[검증됨 2-0]** 한도 초과 시 **다계정/다세션 병렬**로 선형 확장(2계정≈82). 출처: hky035.github.io(blog).
  - ✅ 현 프로젝트는 이미 `kis-websocket.service.ts`에 **구독 한도 초과 → REST 폴링 폴백**을 구현 중(`pollingStockIntervals`). 정확한 한도 수치는 KIS 문서/`kis-api` 스킬로 재확인 권장.
- **[검증됨 3-0]** KIS WS는 **한 연결에서 다종목 동시 구독** 지원(공식 README 예: `kws.subscribe(asking_price, ["005930","000660"])`, tr_id=H0STCNT0 체결가/H0STASP0 호가별 tr_key 등록). 세션당 한도(~41) 내에서. → 동시보유 15종목은 단일 세션으로 충분.

### 1.3 한국시장 특수 규정 (체결·청산 로직에 직접 영향)

- **[검증됨 3-0]** **가격제한폭 ±30%** (KOSPI/KOSDAQ, 2015.6.15 ±15%→±30% 확대 + VI 동시 도입). 출처: BusinessKorea·MDPI·arXiv·KOFIA 교차확인. → 손절/익절 폭 모델링과 상·하한가 미체결 처리에 영향.
- **[검증됨 3-0]** **변동성완화장치(VI)** — **KRX 공식 규정(regulation.krx.co.kr)으로 직접 확인**:
  - 동적 VI(직전 체결가 대비): **KOSPI200 ±3%**(종가단일가 ±2%), **일반·KOSDAQ ±6%**(종가단일가 ±4%). 파생 최종거래일 종가단일가엔 기초주권 ±1% 특례.
  - 정적 VI(전일종가/직전단일가 대비): **±10%**.
  - 발동 시 **약 2분 단일가매매**(임의연장 최대 30초)로 전환 → 주문 누적 후 동시 체결.
  - **[검증됨 3-0, 새 디테일]** **NXT(넥스트레이드)는 동일 상황에서 2분 *매매정지*(취소주문만 허용)** — KRX의 단일가와 처리 방식이 **다름**. 봇이 거래소(KRX/NXT)별로 분기 필요.
  - **봇 함의**: VI 발동 2분간은 **지정가 즉시체결 불가**. ① 매수 미체결/지연, ② 손절 슬리피지 급증, ③ 패닉 청산 위험. → VI/상하한가 상태 감지 후 **주문 보류·재시도 로직** 필요(§3.2, P1-4).
- 시간외 단일가/신용·대주: 단기 스윙 봇은 정규장 위주이므로 우선순위 낮음. 다만 **갭(전일 종가→당일 시가) 리스크**가 일봉 스윙의 최대 비대칭 위험 → 진입 타이밍 모델링과 직결(§3.1).

### 1.4 포지션 사이징 & 손익 관리

- **[검증됨 3-0]** **변동성 타깃팅의 검증된 공식**: 최적 Kelly 비중에 **(1 − VIX 백분위순위)** 를 곱해 고변동 구간 노출 축소. 출처: arxiv 2508.16598(primary). → 시장 국면(지수 변동성)에 따라 전체 익스포저를 줄이는 "포트폴리오 레짐 스케일러"의 이론적 근거.
- **[반증/주의 0-3]** 위 논문의 **구체 성과 수치(연 22~23%, MDD 9~10%)** 는 검증에서 **깨짐** → **인용·신뢰 금지**. (공식은 OK, 백테스트 성과 수치는 믿지 말 것.)
- **[표준사실]** **Fractional Kelly**(풀 켈리의 1/2~1/4)가 실무 표준 — 풀 켈리는 추정오차에 취약해 변동성·파산위험 과대. 출처: medium(blog).
- **[검증됨 3-0]** **ATR 기반 사이징/스탑**: 터틀류 "거래당 자본의 1~2% 리스크", 포지션 크기는 ATR(손절거리)에 반비례, 스탑 = 진입가 − (1.5~2)×ATR. **[검증됨 3-0]** 단, 출처의 **ATR 기본 기간은 N=20**(Wilder 원전 14 아님)이며 "모든 변수는 시장상황에 맞게 조정" 단서. → 현 코드 ATR(14)와 차이는 취향/튜닝 영역. 출처: alphasquare(secondary).
- **함의**: 현 프로젝트의 **ATR 역가중 배분**(`computeVolatilityWeightedInvestments`, 가중 [0.5,2.0]x)은 변동성 타깃팅의 단순형으로 방향이 맞다. 개선 여지는 **거래당 R 기반 사이징**(스탑까지 거리로 수량 결정)과 **시장 레짐 스케일러** 추가.

### 1.5 백테스트 검증의 함정 (1~3일 고회전 전략에 특히 치명적)

- **[검증됨 2-0]** **생존편향(survivorship bias)** 의 충격이 매우 큼:
  - S&P100 모멘텀: 생존편향 백테스트 **CAGR 26%** → 상폐기업 포함 시 **12.2%** (거의 반토막). 출처: quantifiedstrategies(secondary).
  - Nasdaq100: **46% → 16.4%**, MDD **41% → 83%**. → 상폐/관리종목을 빼고 보면 위험을 심각하게 과소평가.
- **[검증됨 3-0]** **과최적화**(백테스트 Sharpe 3.0+가 라이브에서 음수로 — 실증: in-sample 1.59→OOS −0.18, AQR 이평전략 1.2→−0.2), **비용 무시**(양호 전략이 마찰비용 반영 후 거의 0). + **[표준사실]** look-ahead bias. 출처: starqube + Bailey/López de Prado(SSRN), Palomar 교재 교차확인.
- **[검증됨 3-0]** **생존편향**이 성과를 부풀림(현재 상장만 테스트 → 상폐 제외). 실증: CRSP 7.4% vs 9.0%, NIFTY Smallcap +4.94%p 과대. 출처: quantifiedstrategies + CRSP/arXiv.
- **[검증됨 3-0]** **Walk-forward 최적화**가 다중 OOS 구간으로 단일(운 좋은) 검증구간의 거짓 신뢰를 막는 핵심 방어. 출처: quantinsti + Wikipedia + arXiv 교차확인.
  - ✅ 현 프로젝트는 이미 **in-sample(2/3) + OOS(1/3) walk-forward** + OOS 품질 게이트(승률≥45%, PF≥1.1) + **익일 시가 진입 + 거래세 + 슬리피지** 반영 → **동종 오픈소스 대비 검증 성숙도 상위권**. 남은 갭은 생존편향과 롤링 walk-forward(§3.3).

## 2. 현재 프로젝트 진단 (코드 기준)

| 영역 | 현재 구현 | 평가 |
|---|---|---|
| 스크리닝 | `scanAllStocks` walk-forward + `evaluateLongBuyRisk`(유동성 3억, ATR≤10%) + rankScore Top35 | 견고. RVOL·상관·레짐 미반영 |
| 진입 | `executeBuy` 지정가@현재가, 전략별 진입비율(day-trading 40%) | 미체결 리스크, R기반 아님 |
| 청산 | `evaluateAndExecuteSell`: TP/SL/트레일링/본전/최대보유 | **부분청산 없음**, 최대보유 **달력일** 버그성 |
| 사이징 | ATR 역가중 [0.5,2.0]x, 동시15·섹터4 | 방향 OK, R기반·레짐·상관 미흡 |
| 실시간 | WS 체결가 트리거 + 30s 루프 + REST 폴백 | **중앙 레이트리밋 없음**(EGW00201 위험) |
| 검증 | walk-forward + 비용/세금/슬리피지 + 그리드서치 | **생존편향 미보정**, 단일 split |
| 비용 | `DEFAULT_SELL_TAX_PCT=0.18` | 2025년엔 0.15%, 2026 재확인 필요 |

### 강점 (유지)
- walk-forward OOS 분리·품질 게이트, 익일 시가 진입 모델(`useNextOpenForBuy`), 세금·슬리피지 반영 — **백테스트→실거래 갭 축소**가 이미 설계 철학에 박혀 있음.
- 검증 룰과 실전 룰 일치(스캔이 내려준 ATR 동적 TP/SL을 세션이 그대로 사용), 섹터캡·동시보유 상한·변동성 역가중 — **다종목 분산 인프라가 이미 존재**.
- WS 구독 한도 REST 폴백 — KIS WS 41종목 한도를 이미 우회.

### 핵심 갭 (개선 대상)
1. **부분 청산(scale-out) 부재** — "짧게 먹고 빠지기"의 핵심 도구 누락.
2. **생존편향** — `stocks` 테이블이 현재 상장만 → 스캔/백테스트 성과 과대.
3. **레이트리밋 중앙 제어 부재** — 종목 수 증가 시 `EGW00201` 위험.
4. **최대보유 = 달력일** (`maxHoldingDays * 24*60*60*1000`) → 주말 포함 조기 청산.
5. **지정가@현재가 미체결** — 급등 종목 진입 실패.
6. **VI/상하한가 미인지** — 단일가 구간 미체결·슬리피지·패닉.
7. **R기반 사이징·시장 레짐 스케일러 부재**.
8. **거래세 상수 노후화**.

## 3. 개선 플랜 (우선순위·파일 단위)

> 표기: 🟢 즉효/저위험 · 🟡 중간 · 🔴 구조 변경. 각 항목에 대상 파일 명시.

### P1 — 다종목 실행 아키텍처 (사용자 1순위)

**P1-1 🟢 중앙 레이트리미터 (EGW00201 방지)** — `apps/backend/src/kis/kis-order.service.ts`, `kis-quotation.service.ts`
- 모든 KIS REST 호출을 통과시키는 **토큰버킷/큐(예: ~8~10 req/s 보수적 상한, 한도 20의 50%)** 도입. `EGW00201` 수신 시 지수 백오프 + 재시도.
- 종목 수 기반 **동적 폴링 스케줄러**: `pollingStockIntervals`(현재 종목별 5s 개별 setInterval → 버스트 위험)를 **단일 라운드로빈 배치 폴러**로 교체(예: N종목을 batch=ceil(N/슬롯), 간격 1s). 리서치의 DynamicBatchCalculator 패턴.

**P1-2 🟡 부분 청산(scale-out) 도입** — `apps/backend/src/auto-trading/auto-trading.service.ts` `evaluateAndExecuteSell`, 엔티티에 `partialExitDone` 필드
- 2단(또는 3단) 익절: 예) **+1.5%에서 50% 청산 → 나머지는 트레일링**. "짧게 먹고(절반 확정) 추세는 남겨" 패턴.
- 백테스트(`backtest.service.ts simulate`)에도 동일 부분청산 로직 반영해 검증-실전 일치 유지.

**P1-3 🟢 진입 체결률 개선** — `executeBuy` (`orderDvsn`)
- 모멘텀/돌파 진입은 **최유리지정가/시장가성 주문**(미체결 방지) 옵션화, 평균회귀는 지정가 유지. 전략별 `tradeMeta`에 `entryOrderType` 추가.
- 미체결 N초 후 **정정(가격 상향)/취소-재주문** 루틴.

**P1-4 🟡 VI·상하한가 인지** — `kis-websocket.service.ts`/`evaluateAndExecuteSell`
- 실시간 데이터의 VI 발동/상하한 플래그 감지 → 해당 종목 **주문 보류 + 단일가(약 2분) 종료 후 재평가**. 패닉 손절 방지.
- **거래소 분기**: KRX는 VI 시 2분 단일가매매(주문 누적·동시체결), **NXT(넥스트레이드)는 2분 매매정지(취소주문만)** 로 다름 → 주문 라우팅/대기 로직을 거래소별로 분기.
- 임계 참고(확정): 동적 VI KOSPI200 ±3%/일반·KOSDAQ ±6%, 정적 VI ±10%, 가격제한폭 ±30%.

**P1-5 🟢 최대보유 거래일 환산** — `auto-trading.service.ts` (calendar→trading days)
- `maxHoldingDays * 24h` 대신 **거래일 카운트**(보유 후 경과 거래일). 주말/휴장 제외. `signal-freshness.ts`의 거래일 인덱스 패턴 재사용.

### P2 — 리스크/자금관리 & 검증 (2순위)

**P2-1 🟡 거래당 R 기반 사이징** — `scheduled-scanner.service.ts` `computeVolatilityWeightedInvestments`
- 수량 = (자본 × 리스크%(예 0.5~1%)) / (진입가 − 손절가). 손절거리(ATR·동적SL)로 수량 결정 → 종목별 **손실 노출 균등화**(현 역가중보다 원리적).

**P2-2 🟡 시장 레짐 스케일러** — 신규 `libs/strategies/src/utils/regime.ts` + 스캐너
- KOSPI/KOSDAQ 지수의 변동성·추세(예: 지수 20일/60일 MA, 지수 ATR%)로 **전체 익스포저(동시보유 수·종목당 금액) 스케일**. 검증된 Kelly×(1−vol percentile) 아이디어. 고변동·지수 약세 시 노출 축소.

**P2-3 🟡 상관/클러스터 캡** — `scheduled-scanner.service.ts` 필터
- 섹터캡(이미 4/섹터)에 더해 **후보 간 일봉 수익률 상관(예 ρ>0.7) 제한** → 같은 테마 동반 손실 방지.

**P2-4 🔴 생존편향 보정** — `stock.entity.ts`/수집기/`backtest.service.ts`
- 상장폐지·관리종목을 **삭제하지 말고 `delistedAt`/`status` 플래그로 보존**, 스캔/백테스트가 "당시 상장" 종목군으로 평가. 최소한 **현재 성과는 생존편향으로 낙관 편향**임을 리포트에 명시. (리서치: 26%→12% 사례)

**P2-5 🟢 비용 상수 config화 & 갱신** — `backtest.service.ts`
- `DEFAULT_SELL_TAX_PCT`를 env/config로. **2026 실제 세율 공식 확인 후** 반영(보수적으로는 현행 유지). 슬리피지는 유동성 연동(저거래대금일수록 ↑).

**P2-6 🟡 롤링 walk-forward** — `backtest.service.ts`
- 단일 2/3-1/3 → **다구간 롤링 OOS**(앵커드/슬라이딩)로 "운 좋은 구간" 과적합 차단.

### P3 — 스크리닝 고도화 (3순위)

**P3-1 🟢 RVOL(상대거래량) 필터** — `buy-risk-filter.ts`/`scanSingleStock`
- 당일 거래량 / 최근 N일 평균거래량 ≥ 임계(예 1.5~2.0) → "오늘 활발한" 종목 우선. 현 `volume_surge` 변형과 중복 제거하며 스캔 공통 필터로 승격.

**P3-2 🟢 유동성 임계 재튜닝** — `buy-risk-filter.ts` `minAvgTurnover20`
- 현 3억(KRW)은 단타엔 다소 낮을 수 있음 → **종목당 투자금/슬리피지 허용치에 맞춰 상향**(예 10~30억) A/B. (리서치는 절대 임계를 못 박지 못함 → 자체 백테스트로 결정.)
- 일봉만으로 호가 스프레드 불가 → (high−low)/close, 거래대금으로 **유동성 프록시** 보강.

**P3-3 🟡 추세/레짐 게이트** — `scanSingleStock`
- 개별 종목 + **지수 레짐** 동시 게이트(지수 약세장에선 매수후보 축소). P2-2와 연동.
